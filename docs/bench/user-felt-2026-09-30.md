## Methodology

- **One subprocess per (engine, query, scale factor)**; the worker imports the engine (timed as `import_ms`), then runs read+query+materialize once (`first_ms`, the headline) and once more in the same process (`repeat_ms`).
- **Data**: DuckDB `dbgen` Parquet (dates as int32 days since epoch, decimals as float32), read from the OS page cache (files are read once before each scale factor so no engine pays a cold disk).
- **Column pruning**: every engine reads only the columns its query uses. Polars (`scan_parquet`) and DuckDB prune automatically; pandas gets `pd.read_parquet(columns=...)`; MXFrame gets `mx.read_parquet_table(columns=..., dictionary="auto")` (the `scan_parquet` reader, eager) through one helper (`scripts/tpch_user/readers.py::mx_read`); tables the harness itself touches with PyArrow string kernels are read with `dictionary=False`.
- **Engines**: pandas (eager), Polars (lazy `scan_parquet` + `collect()`), DuckDB (SQL over `read_parquet`, also the correctness reference), MXFrame `device="cpu"|"gpu"|"auto"` through the public `LazyFrame` API (plus PyArrow where the LazyFrame layer cannot express a step).
- **Correctness**: each result is compared with DuckDB (row count; integer/string columns exactly; float columns at 1e-6 relative, sorted by key columns; LIMIT queries tolerate ties at the cutoff). inputs are float32; an engine that accumulates in float32 drifts on large sums (`†`), DuckDB sums in double.
- **Hardware**: AMD Ryzen 9 5900X 12-Core Processor (24 cores); GPU: NVIDIA GeForce RTX 3090, 610.57.04, 24576 MiB (`CUDA_VISIBLE_DEVICES=1`). **The machine was shared with other jobs during this run (load average at report time: 1.7 2.5 4.1), so timings are indicative.**
- **Versions**: pandas 3.0.2, polars 1.34.0, duckdb 1.5.1, pyarrow 22.0.0, max ?; mxframe at git `ba27699`. Run took 1 min. Data root: `/home/abhisheksreesaila/Projects/mxframe/data`.

### Query semantics

All engines and the DuckDB reference compute the same query. Where it differs from the official TPC-H text (the mxframe implementations are simplified) the difference is listed here; this is not a TPC-certified benchmark.

- Q2: no region-name join (nation.regionkey = 3), 'BRASS' matched anywhere in p_type, no tie-break columns
- Q4: 'EXISTS' expressed as commit < receipt semi-join (as in spec)
- Q5: no supplier-nation = customer-nation condition, no region filter (all nations)
- Q7: all nation pairs (no FRANCE/GERMANY filter)
- Q8: market share by CUSTOMER nation (Brazil, nationkey 2), all order years, customers in region 1
- Q10: no c_name/c_acctbal/... output columns; groups by (o_custkey, n_name)
- Q11: Germany = nationkey 7, threshold fraction 0.0001 (not 0.0001/SF)
- Q14: returns promo_revenue and total_revenue, not the 100*ratio
- Q15: top supplier = exact equality with max revenue
- Q17: no rounding; sum(l_extendedprice)/7
- Q18: sorted by sum_qty only; no o_totalprice/o_orderdate/c_name columns
- Q19: no l_shipmode / l_shipinstruct predicates
- Q20: no partsupp/lineitem correlation on nation join beyond supplier nationkey 3 (Canada)
- Q21: orders with exactly one late supplier, no 'other supplier on the order' EXISTS
- Q22: as TPC-H apart from avg over positive balances computed in float32
